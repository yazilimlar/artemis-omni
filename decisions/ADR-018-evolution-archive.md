# ADR-018 - Evolution Archive

- **Status:** Accepted
- **Date:** 2026-10-02
- **Extends:** ADR-006, ADR-014, ADR-015, ADR-017

## Context

Artemis has shipped milestones M0-M7, Phase 2, and several governance layers in a short
time. The history exists in git, ADRs, pull requests, registries, and session reports,
but no single surface lets a reader inspect how the project evolved: theory to practice,
stack changes, decisions, milestones, and registry state.

Facts verified on `main` @ `c44de0b`, 2026-10-02:

- `/evolution` exists (`app/evolution/page.tsx`) and is listed in `app/sitemap.ts`. It is
  indexable and presents a public "Evolution & Structure" record built from
  `data/artemisPublicStructure` and `/api/public/artemis-structure`.
- `PRODUCT_REGISTRY.yaml` has `artemis-evolution-console` (`lifecycle: concept`,
  `canonical_route: null`). Whether `/evolution` is that product is recorded as
  UNREVIEWED (inventory C6, U7). The route has no registry entry of its own.
- The site audit (PR #89) flagged the route as unregistered.
- ADR-017 requires every page to use the visual grammar native to its subject. The
  subject here is development history, whose native grammar is timelines, supersession
  graphs, flow diagrams, matrices, and architecture maps.

## Decision

Create the **Evolution Archive**: a living, generated, inspectable record of the
project's evolution, presented at `/evolution`.

### a. Source of truth

Git history, ADRs, pull requests, and registries. The archive is derived from them and is
never hand-edited.

### b. Generated data file

`data/evolution.json`, regenerated by a script after every merge to `main`.

### c. Schema (proposed; not applied to any YAML in this PR)

```json
{
  "version": 1,
  "generated_at": "ISO8601",
  "events": [
    {
      "id": "EVT-<n>",
      "type": "adr_added | adr_superseded | product_registered | product_status_changed | route_added | route_removed | milestone_shipped | pr_merged | registry_changed | security_fix | scene_registered",
      "date": "ISO8601",
      "title": "string",
      "summary": "string",
      "references": ["PR#", "ADR-", "commit-sha", "file-path"],
      "division": "string | null",
      "product": "string | null",
      "outcome": "string"
    }
  ],
  "stats": {
    "adrs_total": 0,
    "adrs_superseded": 0,
    "products_total": 0,
    "products_by_status": { "<status>": 0 },
    "scenes_total": 0,
    "milestones_shipped": 0,
    "prs_merged": 0
  }
}
```

Event ids must be stable across regenerations: derived from the source reference (PR
number, ADR number, commit sha), not from a running counter that shifts when history is
re-read.

### d. Extraction

`scripts/extract-evolution.mjs` reads the sources and writes `data/evolution.json`. A CI
job runs it after every merge to `main`.

**The generated file reaches `main` through a pull request, not a direct push.** The job
opens an automated PR with a bot-style message (for example
`chore(evolution): regenerate data/evolution.json`). This keeps the CLAUDE.md rule that
nothing is pushed directly to `main`, and follows the ADR-013 precondition that an
automation identity must not bypass `main` protection. If the owner prefers a direct
commit, that needs an explicit ruleset exception recorded in a later ADR. The job must
ignore its own merge commits so it cannot loop.

### e. Visualization stack (locked for v1)

| Subject | Visual | Tool |
| --- | --- | --- |
| Timeline | Scroll-driven horizontal timeline | GSAP + ScrollTrigger |
| ADR supersession | Force-directed or hierarchical graph | D3.js |
| Registry flow | Sankey-style flow | Observable Plot |
| Theory-to-practice matrix | Table | Plain HTML table + Tailwind |
| Architecture map | 3D map | MathBox on the existing R3F island |
| Generative art panels (optional) | Images | ComfyUI outputs committed as static assets; never called at runtime |

Constraints carried from earlier ADRs:

- The 3D architecture map is a registered scene under ADR-015 (the ADR-016 precedent
  allows a scene bound to a non-`/labs/scenes` route). It needs a scene-registry entry,
  a passport, the 2D fallback chain, and the validator budgets. Until it passes
  `validate-scenes`, the archive ships without it.
- Every other visual works without JavaScript-heavy 3D, honors reduced motion, and has a
  readable table or list equivalent.
- No third-party runtime fetches. Libraries are bundled, not loaded from CDNs (ADR-015,
  PR #94).
- ComfyUI is self-hosted and offline. Only its committed outputs are served.

### f. New dependencies

Approved for v1, to be installed in the implementation PR, not in this one:

| Package | Purpose | Condition |
| --- | --- | --- |
| `gsap` (with ScrollTrigger) | Timeline | Confirm the current license terms before install |
| `d3` (only the needed modules, e.g. `d3-force`, `d3-hierarchy`) | Supersession graph | Import modules, not the whole bundle |
| `@observablehq/plot` | Registry flow | Check the Sankey support level; fall back to `d3-sankey` if absent |
| `mathbox` | Architecture map | Only if the 3D map is built; verify compatibility with the installed `three` and R3F before install; counts toward the ADR-015 island budget |

Each implementation PR must report the incremental gzipped cost per page. Libraries
that load on `/evolution` must not add to other routes' first-load JS.

Named by the owner but **not approved in this ADR**: Manim-Web, JSXGraph, p5.js. Each
needs its own ADR if adopted. Manim-Web is a stretch goal for algorithm animations.

### g. Visibility

`/evolution` is `internal_operations` and `noindex`. A public-safe subset at
`/evolution/public` may be defined later by a separate decision.

This reclassifies an existing, currently public route. The implementation PR must:

- add `robots: noindex` and remove `/evolution` from `app/sitemap.ts`;
- put the route behind the ADR-011 internal auth, or record the owner's decision to
  keep it open but noindex;
- decide what happens to the current public content and to
  `/api/public/artemis-structure` (move to `/evolution/public`, keep as is, or retire).
  This ADR does not decide that. It must not be removed without a record.
- add a registry entry for the route and resolve the UNREVIEWED link to
  `artemis-evolution-console`.

### h. Update rule

`data/evolution.json` is regenerated, never hand-edited. Manual annotations go in
`docs/history/evolution-notes.md`, which the page may read alongside the JSON. Annotations
reference events by id and never alter them.

## Consequences

- New CI job: `extract-evolution.mjs` on merge to `main`, delivered through an automated
  PR.
- New route responsibilities for `/evolution` (was UNREVIEWED), including the
  reclassification above.
- New generated file: `data/evolution.json`.
- New manual file: `docs/history/evolution-notes.md`.
- One new dependency set: GSAP, D3 modules, Observable Plot, and later MathBox if 3D.
  Each is small, and each is gated by the conditions above.
- Manim-Web, JSXGraph and p5.js stay out of scope until separate ADRs.
- The extractor reads PR data, which requires GitHub API access in CI. It uses the
  workflow's built-in token only; no new secrets (ADR-004).
- Because the archive is derived from the repository, its stats are only as complete as
  the sources. Gaps (for example PRs predating consistent titles) are shown as gaps, not
  filled in.

## Non-goals

- Not a public marketing page. Not indexed.
- Not a real-time dashboard. Regenerated on merge, not streamed.
- Not a replacement for git log or GitHub. A visualization layer on top.
- No user-contributed content.
- No hand-editing of `data/evolution.json`.
